LLM agents vs.
building telemetry.

Can a training-free, evidence-grounded LLM agent framework classify time-series it was never built for? My Master's capstone adapted ZARA - a framework designed for human activity recognition - to Brick building-automation metadata, and measured exactly where zero-shot reasoning holds up and where it breaks.

Course
UNSW · DATA5925 Capstone
Year
2026
Tools
Python, XGBoost, FAISS, LLM agents
Role
Researcher & pipeline builder

01The question

Every sensor in a smart building - temperature, alarm, setpoint, command - needs a label before its data is useful, and labelling them by hand is slow, expensive expert work. The Brick-by-Brick 2024 competition framed this as a classification problem over raw time-series. The winning solutions were trained ensembles.

My capstone asked a different question: ZARA, a training-free LLM agent framework, had shown that evidence-grounded agentic reasoning works for human activity recognition. Does that transfer to a completely different time-series domain - without any task-specific training?

02The pipeline

I built the full system end to end - every stage below feeds evidence, not vibes, to the agents downstream.

STEP 01

Feature engineering

496 engineered features per daily signal - the statistical fingerprint each agent reasons over.

STEP 02

Knowledge base

A 4,095-entry pairwise XGBoost feature-importance knowledge base spanning 91 composite classes, telling the agents which features matter for which distinction.

STEP 03

Retrieval

Class-conditional FAISS retrieval over Mantis-8M time-series embeddings surfaces the most similar labelled examples as candidate classes.

STEP 04

Four-agent decision chain

Feature Selector → Candidate Pruner → Refiner → Adjudicator, each with schema-constrained JSON validation so no agent can hand-wave its output format.

03Results - honestly reported

86.0%
of queries had the true class in the retrieval top ten - the evidence pipeline works.
36.0%
full-pipeline accuracy (macro F1 0.395) on a held-out partition of the official 2024 test set.
57.0%
accuracy for the competition's winning CatBoost ensemble - independently reproduced and verified for a fair baseline.
The interesting result isn't the gap - it's knowing exactly where the gap comes from. Retrieval was fine. The reasoning stage wasn't.

A 21-point shortfall against a trained ensemble could mean anything. So rather than stopping at the headline number, I ran controlled ablations to localise the failure.

04The diagnosis

  • Pruning was a no-op. Disabling the Candidate Pruner agent left accuracy unchanged - one of the four agents was contributing nothing measurable
  • The Adjudicator anchors on rank. A rank-anchoring test showed the final agent defaulted to the top-retrieved candidate 26 to 47 points above chance, and overrode a deliberately misleading rank in only 15-48% of cases. The "reasoning" was substantially rank-following
  • Both paradigms fail the same way. The trained CatBoost model and the zero-shot pipeline converge independently on the same Status/Alarm/Command confusion cluster - evidence the ceiling lies in Brick's functional-role labels themselves, not in either classification paradigm

05Limitations

A negative-leaning result is only worth publishing if its caveats are named as carefully as its claims.

⚠ PARTITION

Held-out partition, not the full set

Evaluation ran on a held-out partition of the official test set, so absolute numbers may shift slightly at full scale - though the baseline was evaluated on the identical partition.

⚠ DETERMINISM

LLM outputs vary between runs

Schema-constrained JSON keeps the format stable, but agent decisions are not perfectly reproducible run-to-run the way a fitted tree ensemble is.

⚠ TRANSFER

One domain pair tested

HAR → building telemetry is a single transfer. The conclusion "reasoning is the bottleneck" is demonstrated here, not proven for agentic time-series classification in general.

⚠ TAXONOMY

The labels themselves are noisy

Brick's functional-role labels blur Status, Alarm and Command. Both model families hitting the same wall suggests part of the "error" is irreducible label ambiguity.

06What it taught me

As a researcher

A rigorous negative result beats an inflated positive one. Reproducing the winning baseline myself - rather than quoting the leaderboard - is what made the comparison honest.

Technically

How to build retrieval-augmented agent systems end to end: embedding stores, class-conditional FAISS indexes, feature-importance knowledge bases, and schema-validated agent chains.

About ablations

"It underperforms" is a headline; "the Adjudicator follows retrieval rank 26-47 points above chance" is a finding. Controlled ablations turn a gap into an explanation.

About agents

Adding agents isn't adding intelligence. One of four agents did nothing measurable - a lesson worth its weight as the industry reaches for agentic everything.
